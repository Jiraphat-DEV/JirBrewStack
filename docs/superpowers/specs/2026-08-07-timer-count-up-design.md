# 01 Timer นับขึ้น กดจบขั้นเอง (Design)

วันที่: 2026-08-07
Branch: `feat/timer-count-up`
req: [01-timer-count-up](2026-08-05-jirbrewstack-v2.1-req/01-timer-count-up.md) · [roadmap](2026-08-05-jirbrewstack-v2.1-roadmap.md)

## 1. เป้าหมาย

กลับด้านโมเดลเวลาของ timer จากนาฬิกาถอยหลังที่เดินเองเป็นนาฬิกานับขึ้นที่รอผู้ใช้กด และเก็บเวลาจริงต่อขั้นไว้เป็นวินาทีเพื่อส่งต่อให้ item 06

ไม่แตะ backend ไม่แตะ auth ไม่แตะโมเดลคำนวณสูตร ไม่เพิ่ม dependency `buildTimerSteps(recipe, picks)` ยังคืน `{ steps, totalTime }` เหมือนเดิม แค่ timer เลิกใช้ `totalTime` กับ `step.startTime` แล้วหันไปใช้ `step.duration` ที่มีอยู่แล้วแต่ไม่เคยมีใครอ่านแทน

## 2. ทำไมต้องเขียน `useTimer.js` ใหม่ทั้งไฟล์

ของที่ hook เดิม export ออกมาใช้กับโมเดลใหม่ไม่ได้สักตัว

| ของเดิม | ทำไมใช้ไม่ได้ |
|---|---|
| `elapsedTime` เดียวสำหรับทั้งการชง | โมเดลใหม่ต้องรู้เวลาแยกต่อขั้น |
| หา step จาก `startTime` สะสม | ขั้นไม่เลื่อนตามเวลาแล้ว ผู้ใช้เป็นคนกด |
| `isComplete` เมื่อ `elapsedTime >= totalTime` | ห้ามมีจุดที่นาฬิกาหยุดเอง |
| `stepTimeRemaining` `totalTimeRemaining` | นับขึ้น ไม่มีคำว่าเหลือ |
| `seek(seconds)` | ย้อนขั้นคือการล้างบันทึก ไม่ใช่การกระโดดเวลา |
| `stepChanged` | ผู้ใช้เป็นคนกดเปลี่ยนขั้นเอง ไม่ต้องเตือนตัวเอง |

แก้ทีละส่วนจะเหลือซากที่ไม่มีใครเรียก เขียนใหม่ทั้งไฟล์ในชื่อเดิม

## 3. แหล่งเวลา

เก็บ `Date.now()` ตอนขั้นเริ่ม แล้วคำนวณเวลาที่ผ่านไปจาก timestamp ทุกครั้งที่ render `setInterval` มีหน้าที่แค่สั่ง re-render ทุก 500 ms ไม่ใช่ตัวนับเลข

ของเดิมบวก 1 ทุกครั้งที่ interval ยิง ซึ่งพอแท็บถูกซ่อนเบราว์เซอร์หรี่ interval เหลือนาทีละครั้ง เวลาที่บันทึกจะน้อยกว่าจริงแบบเงียบๆ ทั้ง item นี้มีอยู่เพื่อจดเวลาจริง จะยอมให้เพี้ยนไม่ได้ ใช้ 500 ms แทน 1000 ms เพื่อให้ตัวเลขวินาทีบนจอตามหลังของจริงไม่เกินครึ่งวินาที

## 4. โมเดลสถานะ

state มีสองตัว ที่เหลือ derive ทั้งหมด

```js
{
  actuals: [],        // number[] เวลาจริงเป็นวินาทีของขั้นที่จบแล้ว
  stepStartedAt: null // timestamp ตอนขั้นปัจจุบันเริ่ม null = ยังไม่เริ่มหรือจบหมดแล้ว
}
```

`actuals.length` เป็น source of truth ตัวเดียวว่าอยู่ขั้นไหน ทำให้ไม่มีทางที่ index กับบันทึกจะไม่ตรงกัน

| ค่า | มาจาก |
|---|---|
| `currentStepIndex` | `actuals.length` |
| `isComplete` | `actuals.length >= steps.length` |
| `isRunning` | `stepStartedAt !== null` (ป้อนให้ `useWakeLock`) |
| `stepElapsed` | `max(0, floor((now - stepStartedAt) / 1000))` เป็น 0 ตอนไม่ running |
| `stepTarget` | `steps[currentStepIndex].duration` เป็น 0 ตอน complete |
| `stepDiff` | `stepElapsed - stepTarget` เก็บเครื่องหมายไว้ |
| `totalElapsed` | `sum(actuals) + stepElapsed` |
| `progress` | `actuals.length / steps.length * 100` นับขั้น ไม่ใช่เวลา |

ไม่มี flag `hasStarted` แยก เพราะ "ยังไม่เริ่ม" คือ `!isRunning && !isComplete` อยู่แล้ว

## 5. การเปลี่ยนสถานะ

สามอัน เขียนเป็น reducer บริสุทธิ์ `now` กับ `stepCount` ส่งเข้าไปทาง action ไม่ให้ reducer เรียก `Date.now()` หรืออ่าน `steps` เอง จะได้เทสด้วย `node --test` ตรงๆ โดยไม่ต้องเพิ่ม testing library

```js
goToStep { index, now }
  actuals -> actuals.slice(0, index)
  stepStartedAt -> now

endStep { now, stepCount }
  ถ้า stepStartedAt เป็น null คืน state เดิม ไม่ทำอะไร
  actuals -> [...actuals, floor((now - stepStartedAt) / 1000)]
  stepStartedAt -> ครบทุกขั้นแล้ว ? null : now

reset
  กลับไปเป็น state ตั้งต้น
```

`เริ่ม` คือ `goToStep({ index: 0 })` ตัวเดียวกับการย้อนขั้น ไม่มีฟังก์ชัน `start` แยก

ตัวห่อฝั่ง React เรียก `Date.now()` ครั้งเดียวต่อการกด แล้วยัดค่าเดียวกันทั้งเข้า action และเข้า state `now` ที่ใช้ render กัน `now` ค้างเก่ากว่า `stepStartedAt` แล้วได้เวลาติดลบ (มี `max(0, ...)` กันไว้อีกชั้น)

**การปัดเศษใช้ `floor` ทั้งการแสดงผลและการบันทึก** ตัวเลขที่บันทึกจึงเท่ากับตัวเลขที่ผู้ใช้เห็นตอนกดเสมอ ยอมเสียค่าเฉลี่ยครึ่งวินาทีต่อขั้นเพื่อไม่ให้เกิดกรณีจอบอก 0:52 แต่บันทึกเป็น 53

## 6. เวลารวมถอยตามเวลาย้อนขั้น

ช่อง "รวม" บอกว่าบันทึกที่ถืออยู่ตอนนี้รวมได้เท่าไหร่ ไม่ใช่ผ่านไปกี่นาทีแล้วในชีวิตจริง การกดย้อนขั้นคือการประกาศว่าที่ทำไปเมื่อกี้ไม่นับ เลขรวมจึงต้องไม่นับตาม

ตัวอย่าง มือลั่นกดจบขั้น 2 เร็วไปทั้งที่น้ำยังเทไม่หมด รู้ตัวตอนอยู่ขั้น 3 ได้ 15 วิ

| เกิดอะไร | นาฬิกาผนัง | `actuals` | ช่องรวมบนจอ |
|---|---|---|---|
| จบขั้น 1 (เป้า 30) | 0:35 | `[35]` | 0:35 |
| จบขั้น 2 (เป้า 40) มือลั่น | 1:20 | `[35, 45]` | 1:20 |
| อยู่ขั้น 3 ได้ 15 วิ | 1:35 | `[35, 45]` | 1:35 |
| กดขั้น 2 ในลิสต์เพื่อย้อนกลับ | 1:35 | `[35]` | 0:35 |
| เทขั้น 2 ใหม่จนจบจริง ใช้ 50 วิ | 2:25 | `[35, 50]` | 1:25 |

60 วิที่ถูกโยนทิ้ง (45 ของขั้น 2 เดิม บวก 15 ที่เดินไปในขั้น 3) หายจากช่องรวมพร้อมกับหายจาก `actuals` ผู้ใช้ไล่บวกเวลาในลิสต์ step แล้วได้เท่ากับช่องรวมเสมอ

ทางเลือกที่ไม่เอาคือให้ช่องรวมเดินหน้าอย่างเดียว ซึ่งจะจบด้วยเลขสองชุดที่ไม่ตรงกัน (จอบอก 2:25 ลิสต์รวมได้ 1:25) โดยไม่มีอะไรบนจออธิบายส่วนต่าง แล้วผลักปัญหาไปให้ item 06 ตัดสินว่าจะบันทึกเลขไหน บวกกับต้องเพิ่ม state ตัวที่สาม (`brewStartedAt`) ที่ไม่ได้ใช้ทำอย่างอื่นเลย

ผลข้างเคียงที่ยอมรับ: นาฬิกากระโดดถอยหลังตอนกดย้อนขั้น ซึ่งผิดสัญชาตญาณของคำว่านาฬิกาจับเวลา แต่ตรงกับความหมายของช่องนี้

## 7. API ของ hook

```js
const timer = useTimer(steps);
```

| คืนอะไร | ชนิด |
|---|---|
| `currentStepIndex` `stepElapsed` `stepTarget` `stepDiff` `totalElapsed` `progress` | number |
| `isRunning` `isComplete` | boolean |
| `actuals` | number[] เวลาจริงต่อขั้น |
| `goToStep(index)` `endStep()` `reset()` | ฟังก์ชัน ไม่รับ `now` ข้างในเรียก `Date.now()` เอง |

`formatTime(seconds)` กับ `formatDiff(seconds)` เป็นฟังก์ชันธรรมดาที่ export จากไฟล์เดียวกัน ไม่ได้อยู่ในสิ่งที่ hook คืน เพราะ `TimerStep.jsx` ก็ต้องใช้ และไม่ได้พึ่ง state อะไรเลย ของเดิมห่อ `formatTime` ด้วย `useCallback` โดยไม่มีเหตุผล

`formatDiff` ยังคืน `null` เมื่อส่วนต่างเป็น 0 เหมือนเดิม นอกนั้นคืน `+12 วิ` หรือ `-5 วิ` `TimerStep.jsx` ใช้ค่านี้ตรงๆ (ไม่เรนเดอร์อะไรตอนตรงเป้า เพราะป้ายเป็นแค่หมายเหตุประจำแถว blank ได้ไม่กระทบอะไร) แต่นาฬิกาหลักใน `Timer.jsx` แทน `null` ด้วยข้อความ `ตรงเป้า` ระหว่างที่นาฬิกากำลังเดิน เพื่อไม่ให้ป้ายส่วนต่างหายไปแล้วดันตัวเลขเวลากลับไปกลางจอชั่วขณะ (ดู §8)

`actuals` ค้างอยู่ใน hook รอ item 06 มาดึง **ยังไม่ต่อ prop ขึ้น `App.jsx`** เพราะ item 06 เป็นคนตัดสินว่าจะส่งผ่าน state ใน `App.jsx` หรือ prop ตรง

### แบ่งเป็นสามชิ้นเพื่อให้เทสได้

| ชิ้น | หน้าที่ | เทสได้ด้วย node --test |
|---|---|---|
| `timerReducer(state, action)` | การเปลี่ยนสถานะ | ได้ |
| `timerView(steps, state, now)` | คำนวณค่า derive ทั้งหมดในตาราง §4 | ได้ |
| `useTimer(steps)` | ห่อ `useReducer` + `setInterval` + `Date.now()` | ไม่ ทำมือ |

ตรรกะทั้งหมดอยู่ในสองชิ้นแรกซึ่งเป็นฟังก์ชันบริสุทธิ์ `useTimer` เหลือแต่ glue ของ React ประมาณ 20 บรรทัด อยู่ไฟล์เดียวกันทั้งสามชิ้น

## 8. UI

### กล่องนาฬิกา

```
┌────────────────────────────┐
│ ขั้นที่ 2/5 · เทน้ำรอบแรก      │
│                            │
│    0:52        +12 วิ       │
│    เป้า 0:40                │
│                            │
│        รวม 2:47            │
└────────────────────────────┘

[ ━━━━━━━━━━━━━━░░░░░░░ ]

     [  จบขั้นนี้  ]   [ ชงซ้ำ ]
```

เวลาในขั้นเป็น `--fs-display` ส่วนต่างเป็น `--fs-xl` อยู่ข้างกัน เป้าเป็นบรรทัดเล็ก `--fs-sm` ใต้เวลา เวลารวมอยู่ล่างสุด `--fs-md`

ส่วนต่างเป็นบวก (เกินเป้า) ใช้ `--color-warning-text` เป็นลบใช้ `--color-text-muted` **ไม่ใช้สีเขียว** เพราะระหว่างที่ยังทำขั้นอยู่ ค่าติดลบแค่แปลว่ายังไม่ถึงเป้า ไม่ได้แปลว่าดี req ข้อ 8 ขอให้อ่านออกจากระยะแขนเฉพาะตัวบอกว่าเกินเป้า

ป้ายส่วนต่างต้องอยู่ตลอดเวลาที่นาฬิกาเดิน แม้วินาทีที่ตรงเป้าพอดี ถึงจะไม่มีตัวเลขให้โชว์ (`formatDiff` คืน `null`) ก็แทนด้วยข้อความ `ตรงเป้า` แทนการซ่อนป้ายทิ้ง เพราะ `.timer__clock` จัดกลางด้วย flex การซ่อนป้ายแล้วโชว์กลับไปมาจะทำให้ตัวเลขเวลาเลื่อนซ้ายขวาทุกครั้งที่ผ่านจุดตรงเป้าพอดี ใช้สีเดียวกับ `--color-text-muted` (คลาส `--under`) เพราะตรงเป้าพอดีไม่ใช่ทั้งเกินและไม่ใช่ทั้งสิ่งที่ต้องเตือน

ตอน complete หัวกล่องเป็น "ชงเสร็จแล้ว" ช่องเวลาในขั้นกับส่วนต่างหายไป เหลือเวลารวมเป็นตัวใหญ่

### ปุ่ม

ปุ่มหลักปุ่มเดียว เปลี่ยนหน้าที่ตามสถานะ

| สถานะ | ข้อความ | ทำอะไร |
|---|---|---|
| ยังไม่เริ่ม | เริ่ม | `goToStep(0)` |
| กำลังชง | จบขั้นนี้ | `endStep()` |
| จบครบแล้ว | ชงเสร็จแล้ว | กดไม่ได้ |

ไม่มีปุ่มหยุดชั่วคราว ตัด `isRunning`/`pause`/`toggle` แบบเดิมทิ้งทั้งหมด ถ้าโดนขัดจังหวะกลางคันก็ย้อนขั้นทำใหม่ ปุ่ม `ชงซ้ำ` (`reset`) ยังอยู่ที่เดิม

### ลิสต์ step

| ขั้น | แสดงเวลาอะไร | กดได้ไหม |
|---|---|---|
| ผ่านมาแล้ว | เวลาจริง + ส่วนต่าง | ได้ `goToStep(index)` |
| ปัจจุบัน | เวลาเดินสด | ไม่ กันกดพลาดแล้วเวลาที่เดินอยู่หาย |
| ข้างหน้า | เป้าจากสูตร | ไม่ `disabled` |

ก่อนกดเริ่ม ทุกขั้นแสดงเป้าและกดไม่ได้ทั้งหมด ตอนชงจบครบแล้ว `currentStepIndex` เท่ากับจำนวนขั้น ทุกขั้นจึงนับเป็น "ผ่านมาแล้ว" และกดย้อนกลับได้หมด ซึ่งตรงกับที่ต้องการคือชงจบแล้วยังกลับไปแก้ขั้นสุดท้ายได้

### ตัดของเดิมทิ้ง

เอฟเฟกต์กะพริบพื้นหลังตอนเปลี่ยนขั้น (`useEffect` ที่ดู `timer.stepChanged` ใน `Timer.jsx` กับ `body.step-change` ใน `Timer.css`) ถูกลบ เพราะผู้ใช้เป็นคนกดเปลี่ยนขั้นเอง ถ้าตัวแปรสี `--color-warning-flash` ใน `index.css` ไม่มีที่อื่นใช้แล้วให้ลบด้วย

`onSeek` บน `TimerStep` เปลี่ยนเป็น `onSelect` และ prop `remaining` เปลี่ยนเป็น `time` กับ `diff`

## 9. เทส

`src/hooks/useTimer.test.js` รันด้วย `node --test` ไม่ต้องเพิ่ม dependency เทส `timerReducer` กับ `timerView` ตรงตามหัวข้อ "วัดผลยังไง" ใน req

| เคส | ยืนยันอะไร |
|---|---|
| กดเริ่มแล้วปล่อยทิ้ง 5 นาที | `currentStepIndex` ยังเป็น 0, `isComplete` false, `stepElapsed` 300, `totalElapsed` 300 |
| จบขั้นช้ากว่าเป้า 20 วิ | ก่อนกด `stepDiff` เป็น `+20` หลังกด `actuals[0]` เป็น 50 ไม่ใช่ 30 |
| ย้อนขั้นตาม timeline §6 | จบที่ `[35, 50]` ไม่ใช่ `[35, 45, 50]` และ `totalElapsed` เป็น 85 |
| จบครบทุกขั้น | `actuals.length === steps.length`, `isComplete` true, `isRunning` false, `totalElapsed === sum(actuals)` |
| กด `endStep` ตอนยังไม่เริ่ม | state ไม่เปลี่ยน |

`package.json` เปลี่ยน script `test` เป็น `node --test` เฉยๆ ให้ node 22 หาไฟล์ `*.test.js` เองทั้งโปรเจกต์ จะได้ไม่ต้องมาต่อชื่อไฟล์ทุกครั้ง `brew.test.js` ต้องยังผ่านเหมือนเดิม ถ้าพังแปลว่าไปแตะสิ่งที่ไม่ควรแตะ

ส่วน UI ทำมือตาม req: เปิดทิ้ง 5 นาทีแล้วไม่มีอะไรประกาศว่าเสร็จ, ย้อนขั้นแล้วเวลานับใหม่, จอไม่ดับตลอดการชง
