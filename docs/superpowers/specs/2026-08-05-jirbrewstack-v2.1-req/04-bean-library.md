# 04 · คลังเมล็ด

กลุ่ม: เมล็ด · ต้องรอ: 03 · ประมาณ 2 วัน
[กลับไป roadmap](../2026-08-05-jirbrewstack-v2.1-roadmap.md)

## ปัญหา

ทุกครั้งที่จะคำนวณสูตร ต้องกดเลือก roast, process, altitude, origin ใหม่ทั้ง 4 ช่อง ทั้งที่ถุงเดิมข้อมูลเหมือนเดิมทุกครั้ง และข้อมูลถุงที่กินแล้วก็หายไปหมด ไม่มีทางย้อนดูว่าเคยกินอะไรมาบ้าง

นี่คือฟีเจอร์ที่แอปกาแฟทุกเจ้าในตลาดมี และเป็นตัวที่ทำให้ item 06 กับ 07 มีความหมาย เพราะบันทึกการชงที่ไม่รู้ว่าชงเมล็ดอะไรก็ไร้ค่า

## ต้องได้อะไร

1. หน้า "เมล็ดของฉัน" เข้าถึงได้จาก header ตอน login แล้ว
2. **เพิ่ม / แก้ / เก็บเข้ากรุ** เมล็ด เก็บที่ `users/{uid}/beans/{beanId}`
3. field ของเมล็ด

   | field | บังคับ | หมายเหตุ |
   |---|---|---|
   | `name` | ใช่ | ชื่อที่เจ้าของเรียก |
   | `roast` | ใช่ | 3 ตัวเลือกเดิมจาก `brewing-rules.js` |
   | `process` | ใช่ | 8 ตัวเลือกเดิม |
   | `altitude` | ใช่ | 3 ตัวเลือกเดิม |
   | `origin` | ใช่ | 6 ตัวเลือกเดิม |
   | `roaster` | ไม่ | |
   | `roastDate` | ไม่ | ถ้ามี ให้แสดงเป็น "คั่วมา N วัน" |
   | `note` | ไม่ | ข้อความอิสระ |

   4 ตัวแรกที่บังคับคือ 4 ตัวแปรที่เครื่องคิดเลขใช้ ถ้าไม่ครบ item 05 เติมให้ไม่ได้ ซึ่งเป็นเหตุผลทั้งหมดที่คลังนี้มีอยู่
4. ตัวเลือกของ 4 field นั้นต้องอ่านมาจาก ruleset ที่แอปใช้อยู่จริง ไม่ใช่รายการที่พิมพ์ซ้ำไว้อีกที่ ไม่งั้นวันที่ ruleset เพิ่ม process ใหม่ คลังเมล็ดจะตามไม่ทัน
5. **ลบคือ `archived: true` ไม่ใช่ลบจริง** เพราะบันทึกการชงอ้างถึงเมล็ดอยู่ ของที่เก็บเข้ากรุแล้วซ่อนจากรายการ มีปุ่มสลับให้ดูได้ และเอากลับออกมาได้
6. รายการเรียงตามวันที่เพิ่มใหม่สุดขึ้นก่อน
7. หน้าว่างตอนยังไม่มีเมล็ด ต้องอธิบายว่าคลังนี้มีไว้ทำอะไร ไม่ใช่ปล่อยว่าง
8. ทำงานตอนออฟไลน์ได้ด้วย Firestore persistence กดเพิ่มตอนเน็ตหลุดแล้วต้องเห็นของที่เพิ่มทันที และมันซิงก์ให้เองตอนกลับมาออนไลน์
9. ไม่ login เข้าหน้านี้ไม่ได้ และเมนูไม่ต้องโผล่ให้เห็นด้วยซ้ำ

## ต้องไม่ทำอะไร

- ไม่ติดตามน้ำหนักคงเหลือ ไม่ติดตามราคา ไม่คำนวณต้นทุนต่อแก้ว
- ไม่มีรูปถ่ายถุง
- ไม่มี import ด้วย QR, บาร์โค้ด, หรือ AI อ่านถุง คลังมีของไม่กี่ถุง พิมพ์เร็วกว่า
- ไม่มีการแจ้งเตือนว่าเมล็ดพักครบแล้วหรือใกล้หมดอายุ
- ไม่มี variety, ไม่มี altitude เป็นตัวเลขจริง (ใช้ 3 ช่วงเดิมเท่านั้น เพราะโมเดลคำนวณรับแค่นั้น) ห้ามเก็บ field ที่ไม่มีอะไรอ่าน
- ไม่แบ่งหน้า โหลดมาทั้งหมดทีเดียว

## จุดที่ต้องตัดสินตอน design

- คนหนึ่งจะมีเมล็ดกี่ถุง ถ้าเกินหลักร้อยการโหลดทั้งหมดจะเริ่มช้า ตอน design ให้เขียนเป็น `ponytail:` กำกับไว้ว่านี่คือเพดานที่รู้ตัว และทางแก้คือแบ่งหน้าเมื่อถึงจุดนั้น
- อ่านด้วย `getDocs` ครั้งเดียวตอนเปิดหน้าตามที่ roadmap ตกลงไว้ แต่ต้องตัดสินว่าหลังเพิ่ม/แก้แล้ว state ในหน้าอัปเดตยังไงโดยไม่ต้องอ่านใหม่ทั้งชุด
- `roastDate` เป็นวันที่ล้วน ไม่มีเวลา ใช้ `<input type="date">` ของ native ไม่เอา date picker จากไลบรารี

## วัดผลยังไง

- เพิ่มเมล็ดครบทุก field แล้วรีเฟรช: ข้อมูลยังอยู่
- เพิ่มเมล็ดโดยไม่ใส่ 4 field ที่บังคับ: บันทึกไม่ได้ และบอกว่าขาดอะไร
- เก็บเข้ากรุแล้ว: หายจากรายการหลัก แต่ยังอยู่ใน Firestore และเอากลับมาได้
- ปิดเน็ต เพิ่มเมล็ด เห็นทันที เปิดเน็ตแล้วเช็คใน Firestore: ของอยู่ครบ
- login ด้วยบัญชีอื่น: ไม่เห็นเมล็ดของบัญชีแรก
- ไม่ login: ไม่มีเมนู "เมล็ดของฉัน" ให้เห็น และถ้าพิมพ์ทางเข้าตรงๆ ก็เข้าไม่ได้
