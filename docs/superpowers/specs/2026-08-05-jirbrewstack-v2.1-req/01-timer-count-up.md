# 01 · Timer นับขึ้น กดจบขั้นเอง

กลุ่ม: Timer · ต้องรอ: ไม่ต้องรออะไร · ประมาณ 2 วัน
[กลับไป roadmap](../2026-08-05-jirbrewstack-v2.1-roadmap.md)

## ปัญหา

timer ของ v2 เป็นนาฬิกาถอยหลังที่เดินเองไม่รอใคร `useTimer(steps, totalTime)` หา step ปัจจุบันจาก `startTime` สะสม แล้วนับถอยหลังจนถึง `totalTime` ก็ประกาศว่าเสร็จ ของจริงคือการเทน้ำ การรอเครื่อง การชั่ง ซึ่งกินเวลาเกินเป้าเสมอ ผลคือนาฬิกาวิ่งนำหน้ามือ

เจ้าของเลิกใช้ timer ในแอปไปแล้ว ใช้ timer ข้างนอกแทน ซึ่งแปลว่าฟีเจอร์นี้ตายทั้งที่เป็นครึ่งหนึ่งของแอป

ฟังก์ชัน `seek` ที่มีอยู่ (ให้กดที่ step แล้วกระโดดไปเวลานั้น) เป็นการแก้อาการ ไม่ใช่แก้เหตุ คอมเมนต์ในโค้ดเองก็เขียนไว้แล้วว่า "ขั้นตอนจริงเสร็จเร็วหรือช้ากว่าเวลาที่ตั้งไว้เสมอ"

## ต้องได้อะไร

1. นาฬิกาหลักนับขึ้นจาก 0 ไม่ใช่นับถอยหลัง และไม่มีจุดที่มันหยุดเอง
2. ขั้นตอนไม่เลื่อนเอง ผู้ใช้กด "จบขั้นนี้" เท่านั้นถึงจะไปขั้นถัดไป
3. ขณะอยู่ในขั้นหนึ่ง ต้องเห็นพร้อมกัน 3 อย่าง: เวลาเป้าหมายของขั้นนั้นจากสูตร, เวลาที่ผ่านไปจริงในขั้นนั้น, และส่วนต่างระหว่างสองค่านั้นแบบมีเครื่องหมาย (เช่น `+12 วิ`, `-5 วิ`)
4. เวลารวมที่ผ่านไปทั้งหมดมองเห็นได้ตลอด
5. ย้อนกลับไปขั้นก่อนหน้าได้ (ทำขั้นนั้นใหม่) การย้อนกลับล้างเวลาจริงของขั้นที่ย้อนไปทิ้ง
6. เมื่อกดจบขั้นสุดท้าย timer อยู่ในสถานะเสร็จ และถือ**เวลาจริงของทุกขั้นเป็นวินาที**ไว้ พร้อมส่งต่อให้ item 06 ใช้
7. กันจอดับระหว่างชงเหมือนเดิม (`useWakeLock`)
8. ตัวบอกว่าเกินเป้าไปเยอะต้องอ่านออกจากระยะแขนตอนมือเปียก ไม่ใช่ตัวเลขเล็กๆ

## ต้องไม่ทำอะไร

- ไม่แตะ Firestore ไม่แตะ auth ไม่เพิ่ม dependency ทำงานได้เต็มที่ตอนไม่ login
- ไม่แตะ `buildTimerSteps()` หรือโมเดลคำนวณสูตร รับ steps เข้ามาเหมือนเดิม เปลี่ยนแค่วิธีเดินเวลา
- ไม่มีเสียง ไม่มีการสั่น (ยังไม่ตัดสินใจ ถ้าจะมีคุยกันทีหลัง)
- ไม่มีการเตือนอัตโนมัติเมื่อเกินเป้า เพราะจุดประสงค์ทั้งหมดคือเลิกให้นาฬิกาเป็นคนสั่ง

## จุดที่ต้องตัดสินตอน design

- `useTimer.js` เดิมจะแก้หรือเขียนใหม่ contract ปัจจุบัน (`startTime` สะสม, `totalTime`, `isComplete` อัตโนมัติ, `seek`) ใช้กับโมเดลใหม่ไม่ได้เลย
- `step.duration` ปัจจุบันมีอยู่แล้วแต่ `useTimer` ไม่เคยอ่าน โมเดลใหม่ต้องใช้มันเป็นเป้าหมาย
- ปุ่ม "หยุดชั่วคราว" ยังต้องมีไหมเมื่อนาฬิกาไม่บังคับอะไรแล้ว
- `progress` bar วัดจากอะไรเมื่อไม่มีเวลารวมที่แน่นอน (นับเป็นจำนวนขั้นที่ผ่านแทนเวลา)
- `stepChanged` ที่ใช้กะพริบพื้นหลังยังจำเป็นไหมเมื่อผู้ใช้เป็นคนกดเปลี่ยนขั้นเอง

## วัดผลยังไง

- เปิด timer ทิ้งไว้ 5 นาทีโดยไม่กดอะไร: ยังอยู่ขั้นที่ 1 นาฬิกาขึ้นถึง 5:00 ไม่มีอะไรประกาศว่าเสร็จ
- กดจบขั้นช้ากว่าเป้า 20 วินาที: ขั้นนั้นแสดง `+20 วิ` และเวลาจริงที่บันทึกไว้คือเวลาที่ผ่านไปจริง ไม่ใช่เป้า
- ย้อนกลับ 1 ขั้นแล้วทำใหม่: เวลาจริงของขั้นนั้นถูกนับใหม่ ไม่ใช่บวกทับของเดิม
- จบครบทุกขั้น: ได้ค่าเวลาจริงครบทุกขั้น จำนวนเท่ากับจำนวน step
- จอไม่ดับตลอดการชง
- `bun run test` ผ่าน (เทสของ `brew.js` ไม่ควรได้รับผลกระทบ ถ้าพังแปลว่าไปแตะสิ่งที่ไม่ควรแตะ)
