# 11 · Override รายคน (ส่วน "ขั้นสูง")

กลุ่ม: Rules · ต้องรอ: 03, 10 · ประมาณ 2 วัน
[กลับไป roadmap](../2026-08-05-jirbrewstack-v2.1-roadmap.md)

## ปัญหา

ตัวเลขทั้งหมดใน `brewing-rules.js` derive มาจากเครื่องมือของเจ้าของ: เลขหน้าปัด Mavo Phantox Pro, กาที่อ่านอุณหภูมิแบบหนึ่ง, โดสฐานที่เลือกไว้ คนอื่นที่เครื่องบดคนละยี่ห้อหรือกาอ่านต่างไป จะได้สูตรที่เพี้ยนอย่างเป็นระบบทุกครั้ง แล้วต้องมาแก้ด้วยมือทุกครั้งเหมือนกันหมด

item นี้คือส่วน "มือโปร" ที่ตกลงกันไว้ และเป็นสิ่งเดียวที่ทำให้ v2.1 ใช้ได้กับคนที่ไม่ใช่เจ้าของ

## ต้องได้อะไร

1. หัวข้อ **"ขั้นสูง"** ที่พับไว้ตั้งแต่แรกบนหน้าสูตร กางเองเมื่อกด **ไม่มีสวิตช์โหมด ไม่มี state ค้างข้ามการเปิดแอป** คนที่ไม่กดต้องไม่รู้สึกว่ามีอะไรเพิ่ม
2. ปรับได้ 4 อย่างเท่านั้น เก็บที่ `users/{uid}/overrides/ruleset`

   | override | ความหมาย |
   |---|---|
   | `grind` offset | เครื่องบดคนละตัว เลขหน้าปัดไม่ตรงกัน |
   | `temp` offset | กาอ่านอุณหภูมิคลาดไป |
   | `dose` ต่อเครื่อง | ใช้โดสฐานไม่เท่ากับ base |
   | `water` ต่อเครื่อง | ใช้ปริมาณน้ำฐานไม่เท่ากับ base |

   แยกค่าของ AeroPress กับ Delter ออกจากกันเด็ดขาด ตามหลักการข้อ 1 ของ v2 ที่ห้ามสองเครื่องใช้ค่าร่วมกัน
3. **offset ใช้หลัง patch ครบทั้ง 4 ขั้นและหลังปัด grind แล้วปัดใหม่อีกที** ไม่ใช่ไปแทรกกลางกระบวนการ ไม่งั้นจะไปชนกับ `tempClamp` และกฎอื่นในโมเดลที่ตั้งใจให้ทำงานตามลำดับ
4. **override ห้ามเงียบ** ถ้าค่าถูกปรับ ต้องเขียนบนการ์ดสูตรว่าปรับอะไรไปเท่าไหร่ (เช่น "ปรับตามเครื่องคุณ: บด +0.5, อุณหภูมิ -1") ตลอดเวลาที่ override มีผล ไม่ใช่แค่ตอนอยู่ในส่วนขั้นสูง นี่คือหลักการข้อ 10 และเป็นสิ่งที่กันปัญหา "ทำไมสูตรฉันไม่เหมือนของเธอ" ที่ไล่ไม่ถูก
5. ปุ่มล้างค่ากลับเป็น 0 ทั้งหมด
6. **บันทึกการชง (item 06) ต้องเก็บ `resolved` ที่ผ่าน override แล้ว** เพราะนั่นคือสิ่งที่แอปสั่งจริง และควรเก็บค่า override ณ ตอนนั้นไว้ด้วยเพื่อให้ประวัติอธิบายตัวเองได้
7. **ลิงก์แชร์ (item 08) พกค่าที่ผ่าน override แล้ว** ซึ่งเป็นเหตุผลข้อหนึ่งที่ item 08 ตัดสินว่าจะพกค่าที่คำนวณเสร็จแทน input
8. ไม่ login: หัวข้อ "ขั้นสูง" ไม่มี หน้าสูตรเหมือน v2 ทุกอย่าง
9. ค่า override ต้องมีเพดาน ไม่ให้ใส่จนสูตรเป็นเรื่องตลก (เช่น จำกัด grind offset ที่ ±2.0 และ temp offset ที่ ±5)

## ต้องไม่ทำอะไร

- ไม่ให้ override ตาราง patch (roast, process, altitude, origin) นั่นคือความรู้เรื่องกาแฟที่เป็นจุดขายของแอป ไม่ใช่การชดเชยเครื่องมือ ถ้าเปิดให้แก้ตรงนั้นได้ก็เท่ากับ fork ruleset ซึ่งตัดออกไปแล้วตั้งแต่ตอนคุยขอบเขต
- ไม่ให้ override `steep`, `pressSpeed`, `bypass`, `preinfusionWait` ค่าพวกนี้เป็นเรื่องของสูตร ไม่ใช่เรื่องของเครื่องมือ และ slider ที่มีอยู่แล้วก็ให้เลือกในช่วงได้อยู่
- ไม่แชร์ override ให้คนอื่น
- ไม่มี preset สำเร็จรูปตามยี่ห้อเครื่องบด (ต้องมีข้อมูลเทียบที่ไม่มีอยู่จริง ตัวแปลง C40/C2 ที่มีอยู่ก็ยังมี bias ที่วัดได้และเลือกจะไม่ชดเชย)

## จุดที่ต้องตัดสินตอน design

- ปัดค่าหลังใส่ offset ยังต้องเป็นทวีคูณของ 0.5 ตามหลักการข้อ 7 ของ v2 แปลว่า offset เองก็ควรถูกจำกัดให้เป็นทวีคูณของ 0.5 ด้วย ไม่งั้นปัดแล้วผู้ใช้จะเห็นว่าค่าที่ใส่ไปไม่มีผล
- `temp` มี `tempClamp` จาก `panamaGeisha` ที่บีบช่วงอยู่ ต้องตัดสินว่า offset ของผู้ใช้อยู่ก่อนหรือหลัง clamp ข้อเสนอ: หลัง เพราะ clamp เป็นความรู้เรื่องกาแฟ ส่วน offset เป็นการชดเชยเครื่องมือที่ควรมีผลกับค่าสุดท้ายที่ผู้ใช้จะไปตั้งบนกาจริง
- เปลี่ยน `dose`/`water` แล้ว ratio ที่แสดงบนการ์ดเปลี่ยนตาม และตารางแก้รสที่มีข้อความว่า "แอปล็อกโดสไว้ที่ base" ต้องแก้ถ้อยคำให้ตรงกับความจริงใหม่
- โหลด override ตอนไหน ต้องไม่ทำให้เครื่องคิดเลขรอเหมือนกับกฎข้อ 9 ข้อเสนอ: ไม่มี override จนกว่าจะโหลดเสร็จ แล้วค่อยคำนวณใหม่

## วัดผลยังไง

- ใส่ grind offset +0.5: ทุกสูตรที่คำนวณได้ขยับขึ้น 0.5 และการ์ดเขียนบอกว่าปรับแล้ว
- ใส่ temp offset -1 แล้วเลือก `panamaGeisha` (ที่มี clamp 85-87): ได้ 84 ถึง 86 ไม่ใช่โดน clamp ดึงกลับ
- เปลี่ยน dose ของ AeroPress: dose ของ Delter ไม่ขยับ
- ล้างค่า: สูตรกลับไปเท่ากับตอนไม่มี override เป๊ะ
- บันทึกการชงตอนมี override: `resolved` ในบันทึกคือค่าที่ผ่าน override แล้ว
- คัดลอกลิงก์ตอนมี override แล้วเปิดในบัญชีอื่น: ได้ตัวเลขเดียวกับคนส่ง
- ไม่ login: ไม่มีหัวข้อ "ขั้นสูง" และสูตรเท่ากับ v2 เป๊ะ
- ใส่ offset เกินเพดาน: ใส่ไม่ได้ หรือถูกดึงกลับเข้าเพดานพร้อมบอกเหตุผล
