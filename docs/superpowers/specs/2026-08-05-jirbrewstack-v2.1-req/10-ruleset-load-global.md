# 10 · โหลด global ruleset จาก Firestore

กลุ่ม: Rules · ต้องรอ: 02, 09 · ประมาณ 1 วัน
[กลับไป roadmap](../2026-08-05-jirbrewstack-v2.1-roadmap.md)

## ปัญหา

ตัวเลขทั้งหมดอยู่ใน `brewing-rules.js` ในโค้ด แก้ทีต้อง commit และ deploy ใหม่ ซึ่งเป็นเหตุผลหนึ่งที่ทำ v2.1 แต่การย้ายขึ้น Firestore มีกับดักที่ต้องกันไว้ตั้งแต่ต้น: **ถ้าเครื่องคิดเลขต้องรอเน็ตก่อนถึงจะคำนวณได้ แอปจะแย่ลงกว่าเดิม** โดยเฉพาะตอนยืนชงในครัวที่สัญญาณไม่ดี

## ต้องได้อะไร

1. **`brewing-rules.js` ในโค้ดยังอยู่และเป็นค่าตั้งต้นที่ใช้ทันทีตอนเปิดแอป** ไม่มีจอโหลด ไม่มีการรออะไรทั้งนั้น คำนวณได้ตั้งแต่วินาทีแรก
2. เพิ่ม field `version` เข้า `brewing-rules.js` เพื่อให้เทียบกับตัวใน Firestore ได้
3. พร้อมกันนั้นอ่าน `rulesets/global` จาก Firestore ถ้าอ่านได้ ผ่าน `validateRuleset` และ `version` ต่างจากตัวในโค้ด ให้สลับมาใช้ตัวจาก Firestore แล้วคำนวณสูตรใหม่
4. **ถ้าอ่านไม่ได้ ไม่มี doc หรือ validate ไม่ผ่าน: ใช้ตัวในโค้ดต่อ log ลง console ไม่แสดงอะไรกับผู้ใช้** ruleset ที่เสียต้องไม่มีทางทำให้แอปพัง มันแค่ไม่ถูกใช้
5. อ่านตอนไม่ login ได้ (rules อนุญาตแล้วใน item 02) ไม่งั้นคนที่ไม่มีบัญชีจะติดอยู่กับ ruleset เก่าตลอดไป
6. Firestore persistence cache ตัวนี้ไว้ เปิดครั้งที่สองตอนออฟไลน์ยังได้ ruleset ล่าสุดที่เคยโหลดมา
7. อ่านครั้งเดียวตอนเปิดแอป ไม่ใช้ realtime listener
8. ถ้ามีการสลับ ruleset ระหว่างที่ผู้ใช้เลื่อน slider ค้างไว้ ค่าที่เลือกต้องไม่กระโดดมั่ว ต้องตัดสินพฤติกรรมตอน design

## ต้องไม่ทำอะไร

- ไม่ลบ `brewing-rules.js` ออกจากโค้ด มันคือ fallback และเป็นสิ่งที่ `brew.test.js` รันด้วย
- ไม่ทำ UI แสดงว่ากำลังใช้ ruleset เวอร์ชันไหน (ถ้าจำเป็นตอน debug ให้ log ลง console พอ)
- ไม่มีปุ่มบังคับโหลด ruleset ใหม่
- ไม่เขียนอะไรลง Firestore item นี้อ่านอย่างเดียว
- ไม่รองรับ ruleset หลายชุด มี `global` ชุดเดียว

## จุดที่ต้องตัดสินตอน design

- ตอน ruleset สลับ ค่าที่ผู้ใช้เลื่อน slider เลือกไว้จะโดนอะไร ข้อเสนอ: ถ้าค่าที่เลือกยังอยู่ในช่วงใหม่ ให้คงไว้ ถ้าหลุดช่วงให้ดึงกลับเข้าขอบที่ใกล้ที่สุด ห้ามรีเซ็ตกลับค่ากลางเพราะผู้ใช้จะงงว่าทำไมค่าที่ตั้งไว้หาย
- การสลับจะเกิดตอนไหน ถ้าสลับตอนผู้ใช้อยู่ใน timer กลางการชง จะยิ่งแย่ ข้อเสนอ: สลับได้เฉพาะตอนอยู่หน้าสูตร ถ้าอยู่ใน timer ให้รอจนออกมา
- ruleset ที่โหลดมาจะเก็บไว้ตรงไหนใน `App.jsx` และส่งลงไปยัง component ที่ตอนนี้ `import rules from '../data/brewing-rules.js'` ตรงๆ อยู่ (`Timer.jsx` เป็นตัวอย่าง) ทุกที่ที่ import ตรงต้องเปลี่ยนมารับผ่าน prop หรือ context ไม่งั้นบางส่วนของหน้าจะใช้ ruleset คนละตัวกัน
- `version` เป็นเลขจำนวนเต็มที่นับขึ้น หรือเป็น timestamp ต้องเลือกให้เทียบง่ายและ item 12 bump ได้โดยไม่ผิดพลาด

## วัดผลยังไง

- ตัดเน็ตทั้งหมดแล้วเปิดแอปครั้งแรก: คำนวณสูตรได้ปกติด้วยค่าจากโค้ด
- ใส่ ruleset ที่ `version` สูงกว่าและอุณหภูมิต่างไปลง Firestore: เปิดแอปแล้วได้ค่าใหม่
- ใส่ ruleset ที่เสีย (`steap` แทน `steep`) ลง Firestore: แอปใช้ค่าจากโค้ดต่อ ไม่มีอะไรพัง มี log ใน console
- ลบ doc `rulesets/global` ทิ้ง: แอปยังทำงานปกติ
- ไม่ login: ยังได้ ruleset ล่าสุดจาก Firestore
- โหลดหน้าครั้งแรก: ไม่มีช่วงที่หน้าจอว่างหรือค้างรอเน็ต
- `bun run test` ผ่านเหมือนเดิม (เทสยังรันกับไฟล์ในโค้ด)
